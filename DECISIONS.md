# DECISIONS

## 2026-07-16 — Cloudflare как платформа пилота

Решение: после завершения основного документооборота развернуть закрытый пилот на Cloudflare Workers. Next.js адаптировать через OpenNext; документы хранить в приватном R2; локальный append-only журнал заменить реализацией поверх D1 либо PostgreSQL.

Причина: единая платформа для web/runtime, файлов, секретов, preview и будущих фоновых задач. Деплой откладывается до появления storage adapter, авторизации, резервного копирования и проверки форм документов.

Не является решением: помещать `data/raw`, печать, подпись или бухгалтерские документы в Worker bundle, Static Assets либо Git.

Источник технического направления: официальная документация Cloudflare Next.js on Workers, актуализирована 05.06.2026.

## ADR-001: сначала пилот, затем SaaS

Решение: проверять продукт на реальном документообороте ИП «Гранд Мебель» до продажи подписки.

## ADR-002: подписка

Решение: основная коммерческая модель — подписка с включёнными AI-операциями. Разовая продажа возможна позднее для корпоративной установки.

## ADR-003: реальные данные вне Git

Решение: оригиналы хранятся рядом с проектом, но исключены из истории репозитория.

## ADR-004: AI не принимает юридически значимые решения

Решение: ИИ извлекает и предлагает; правила считают; человек подтверждает.

## ADR-005: песочница является частью продукта

Решение: закрытая песочница нужна для пилота, публичная — для продажи и обучения.

## ADR-006: продажа является центральной операцией

Решение: счёт остаётся коммерческим требованием оплаты. Учётное событие возникает при проведении продажи, которая формирует З-2 и/или Р-1, складское движение и ЭСФ-обязательство.

## ADR-007: проведение и реверс

Решение: проведённые документы не переписываются незаметно. Исправления сохраняют историю через версию, отмену проведения или реверсивную операцию.

## ADR-008: AI-помощник как управляемый workflow

Решение: диалоговая панель ведёт пользователя по состояниям и предлагает доменные действия. Модель не имеет прямого доступа на запись в бухгалтерскую базу.

## ADR-009: архив сначала проходит карантин

Решение: загруженный архив не распаковывается напрямую в рабочую базу. Сначала выполняются проверки безопасности, манифест и пользовательское подтверждение.

## ADR-010: база знаний с происхождением фактов

Решение: каждое извлечённое значение и ответ по документам сохраняет ссылку на источник. Факты, правила и предположения отображаются раздельно.

## ADR-011: целочисленные тийны для денег

Решение: все денежные значения хранятся как целые числа тийнов (1 KZT = 100 тийн). Никаких float-арифметик.

Причина: избежать ошибок округления при расчёте скидок, итогов и НДС. Тийны — наименьшая единица KZT.

## ADR-012: repository interfaces перед локальным хранилищем

Решение: интерфейсы репозиториев определены в `lib/domain/repository.ts`, реализации — в `lib/storage/local-repositories.ts`.

Причина: подготовка к миграции на Cloudflare D1/R2 без переписывания бизнес-логики. Dependency inversion.

## ADR-013: state machine для документов

Решение: статусы Order (draft→confirmed→cancelled) и Invoice (draft→confirmed→posted, cancelled) управляются state machine с явными переходами.

Причина: защита от невалидных переходов, документирование жизненного цикла, трассировка в audit log.

## ADR-014: append-only audit log через файловые события

Решение: каждое действие (создание, подтверждение, отмена) записывается отдельным JSON-файлом с timestamp и idempotency key.

Причина: трассируемость, откат через реверс, совместимость с будущим D1. Без перезаписи существующих событий.

## ADR-015: PDF на pdf-lib с StandardFonts

Решение: генерация PDF через pdf-lib со встроенными StandardFonts Helvetica. Кастомные шрифты откладываются до решения проблемы с кириллицей.

Причина: pdf-lib轻量, не требует headless chromium. StandardFonts работают без внешних файлов, но не поддерживают кириллицу.
