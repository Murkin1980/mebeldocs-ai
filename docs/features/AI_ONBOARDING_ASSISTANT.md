# AI-помощник подключения компании

## Назначение

Диалоговый помощник сопровождает нового мебельщика от пустого кабинета до готовой базы контрагентов, номенклатуры и истории документов.

Помощник не является свободным чат-ботом, который самостоятельно меняет бухгалтерские данные. Каждый разговор относится к сценарию и имеет состояние, план, вложения, предложения и подтверждения пользователя.

## Точка входа

На каждом экране доступна кнопка «AI-помощник». На первом входе открывается широкая панель:

> Давайте настроим вашу компанию. Я помогу собрать документы, проверю архив и подготовлю базу. Сначала ничего не будет изменено или отправлено.

Основные действия:

1. «Подключить существующие документы».
2. «Начать с пустой базы».
3. «Задать вопрос».
4. «Продолжить незавершённый импорт».

## Сценарий подготовки архива

Помощник объясняет, как создать ZIP на Windows, macOS и телефоне.

### Что положить в папку

- реквизиты ИП/ТОО;
- карточки контрагентов;
- счета;
- договоры и спецификации;
- накладные З-2;
- акты Р-1/ЭАВР;
- ЭСФ XML/PDF;
- банковские выписки;
- справочник товаров и услуг;
- используемые шаблоны документов;
- печать и подпись — только по желанию, в отдельной папке.

### Что не передавать

- пароль ЭЦП;
- пароль интернет-банкинга;
- API-ключи;
- файлы ключей ЭЦП без отдельной необходимости;
- личные документы, не относящиеся к учёту.

### Инструкция Windows

1. Создать папку `Бухгалтерия для импорта`.
2. Разложить файлы по рекомендуемым подпапкам.
3. Нажать правой кнопкой → «Сжать в ZIP-файл»/«Отправить → Сжатая ZIP-папка».
4. Загрузить ZIP в окно помощника.

Помощник предлагает скачать пустую структуру папок и контрольный список.

## Приём архива

Архив проходит карантин до чтения:

1. Проверка расширения, размера и контрольной суммы.
2. Защита от zip-slip, zip-bomb и вложенных исполняемых файлов.
3. Проверка на вредоносное содержимое.
4. Инвентаризация без изменения оригиналов.
5. Классификация чувствительности.
6. Создание закрытой рабочей копии.

Статусы: `uploaded`, `quarantined`, `scanned`, `inventory_ready`, `needs_user_input`, `approved_for_extraction`, `extracted`, `reviewed`, `imported`, `archived`, `rejected`.

## Анализ

Помощник строит кандидаты:

- профиль компании;
- банковские счета;
- контрагенты по БИН/ИИН;
- договоры;
- номенклатура;
- счета, продажи, платежи, З-2, Р-1, ЭСФ;
- связи между документами;
- версии и дубли.

Для каждого поля сохраняются:

- извлечённое значение;
- источник и страница/ячейка;
- уверенность;
- альтернативные варианты;
- решение пользователя;
- версия парсера/модели.

## Отчёт пользователю

Помощник не показывает технический журнал. Он формирует четыре понятные группы:

### Готово к импорту

Однозначные сведения с надёжным источником.

### Нужно подтвердить

Например, два адреса одного контрагента или разные варианты договора.

### Возможные ошибки

- повторный номер;
- неверная сумма прописью;
- несовпадение номера файла и документа;
- отсутствующий БИН;
- разные названия одного контрагента;
- товар записан как услуга;
- нет закрывающего документа;
- возможный дубль ЭСФ;
- платёж не сопоставлен со счётом;
- дата ЭСФ выходит за рассчитанный срок.

### Не удалось прочитать

Скан низкого качества, повреждённый файл, защищённый PDF или неизвестный формат.

## Исправления

Для каждой проблемы доступны действия:

- принять предложенное исправление;
- выбрать один из вариантов;
- оставить как есть;
- отложить;
- применить правило к похожим случаям;
- открыть источник;
- спросить объяснение.

Система никогда не переписывает оригинал. Исправление создаёт нормализованную запись или новую версию документа.

## Подтверждение импорта

Перед импортом показывается сводка:

- сколько компаний;
- сколько контрагентов;
- сколько позиций;
- сколько документов каждого типа;
- сколько связей восстановлено;
- сколько проблем осталось;
- какие даты и периоды затрагиваются.

Пользователь выбирает:

1. Импортировать только подтверждённое.
2. Импортировать подтверждённое и оставить задачи на проверку.
3. Вернуться к исправлениям.
4. Удалить рабочую копию и отменить импорт.

## База знаний компании

База знаний не является одной свалкой текста. Она состоит из слоёв:

1. Структурированные данные: компания, контрагенты, номенклатура, договоры.
2. Документный архив: оригиналы и версии.
3. Связи: заказ, счёт, платёж, реализация, закрытие, ЭСФ.
4. Правила компании: нумерация, шаблоны, условия оплаты, роли.
5. Поисковый индекс: фрагменты документов с обязательной ссылкой на источник.
6. Исправления пользователя: подтверждённые соответствия и предпочтения.

Ответ помощника должен различать:

- факт из документа;
- правило законодательства;
- вывод системы;
- предположение, требующее подтверждения.

## Постоянный помощник после подключения

Примеры команд:

- «Создай счёт для этого клиента».
- «Какие документы не закрыты?»
- «Покажи неоплаченные счета».
- «Почему ты считаешь эти документы дублями?»
- «Что нужно подготовить по этой продаже?»
- «Найди договор с этим контрагентом».
- «Проверь сроки ЭСФ».

Каждый ответ содержит действия, но юридически значимые действия требуют отдельного подтверждения.

## Удаление и повторный импорт

Пользователь может удалить исходный архив, рабочие извлечения или всю базу компании. Повторный импорт использует хеши и не создаёт повторно уже известные файлы.
