# MebelDocs AI

Закрытый пилот и будущий SaaS для автоматизации документооборота мебельных ИП Казахстана.

Канонический паспорт проекта: `PROJECT.md`. Проект ведётся автономно от истории чатов.

Первый контур: текст/голос → подтверждение → счёт → договор/спецификация → З-2 и/или Р-1 → контроль ЭСФ → архив и сверка оплаты.

## Статус

Этап 1: архив инвентаризирован, сущности и статусы ЭСФ нормализованы, первичные связи документов и платежей восстановлены, собран локальный пилотный снимок. Пилотная компания — ИП «Гранд Мебель». Реальные документы хранятся локально в `data/raw/` и исключены из Git.

## Документы проекта

- `PRODUCT.md` — продукт, пользователи, границы MVP.
- `ROADMAP.md` — этапы и критерии выхода.
- `CHECKLISTS.md` — проверочные листы по этапам.
- `ARCHITECTURE.md` — целевая архитектура.
- `DATA_SOURCES.md` — источники и правила импорта.
- `COMPLIANCE.md` — юридические ограничения и контроль.
- `SECURITY.md` — защита данных.
- `AI_INFRA_DECISION.md` — где применять ИИ, а где детерминированные правила.
- `DESIGN.md` — принципы интерфейса и песочницы.
- `AGENTS.md` — правила для AI-кодеров.
- `SESSION_NOTES.md` — журнал рабочих сессий.
- `docs/STITCH_EXPERIMENT_GUIDE.md` — готовый сценарий эксперимента с интерфейсом в Google Stitch.
- `docs/STITCH_NEXT_SCREENS.md` — очередь и готовые промпты следующих экранов Google Stitch.
- `design/stitch/` — изолированное хранилище исходников, экранов и code export из Google Stitch.

## Ближайший результат

Локальный веб-прототип: разбор архива, подтверждение найденных сущностей и постоянный диалог с AI-помощником.

## Запуск веб-прототипа

```bash
cd apps/web
npm install
npm run dev
```

Откройте `http://localhost:3000`. Интерфейс работает в режиме песочницы и не выполняет внешнюю отправку.

Маршрут `GET /api/pilot` читает локальный `data/working/pilot_snapshot` только на сервере и возвращает браузеру обезличенные агрегаты. Если снимок недоступен, интерфейс автоматически использует безопасные демо-данные.

Решения по проверке сохраняются через `POST /api/reviews/{reviewId}/decision` как отдельные append-only события в закрытом `data/working/audit/review-events`. Повтор запроса с тем же ключом идемпотентности не создаёт второе событие.
