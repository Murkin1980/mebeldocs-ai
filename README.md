# MebelDocs AI

Закрытый пилот и будущий SaaS для автоматизации документооборота мебельных ИП Казахстана.

Канонический паспорт проекта: `PROJECT.md`. Проект ведётся автономно от истории чатов.

## Текущий статус

Пилотная компания — ИП «Гранд Мебель».

Проект находится на стадии **локального функционального MVP и подготовки закрытого облачного пилота**.

Реализовано:

- инвентаризация архива и безопасный локальный пилотный снимок;
- нормализация ЭСФ, группировка версий документов и первые связи с платежами;
- полный вертикальный сценарий `профиль → контрагент → заказ → счёт → подтверждение → PDF → audit log`;
- денежные расчёты в целых тийнах;
- state machine для заказов и счетов;
- append-only audit log и идемпотентность команд;
- учёт платежей, привязка платежа к счёту, остаток и сторнирование;
- импорт и проверка ЭСФ XML;
- серверные ограничения доступа на операции записи;
- локальный интерфейс заказов, счетов, аудита и проверки импортированных данных;
- 199 автоматических тестов по состоянию последнего функционального этапа.

Критические ограничения перед пилотом:

- PDF требует окончательной проверки кириллицы и визуального рендера;
- часть новых платежных и ЭСФ-сценариев требует завершения UI и smoke-тестов;
- runtime всё ещё зависит от локального `node:fs`;
- Cloudflare preview, D1/PostgreSQL, private R2, backup/restore и CI ещё не завершены;
- полноценная пользовательская аутентификация и мультитенантность не готовы.

Подробный актуальный статус и порядок следующих этапов: `NEXT_STAGES_PLAN.md`.

## Целевой первый контур

`текст/голос → подтверждение → счёт → договор/спецификация → З-2 и/или Р-1 → контроль ЭСФ → архив → сверка оплаты`

ИИ предлагает и объясняет, но денежные расчёты, статусы и необратимые действия выполняются детерминированно и только после подтверждения.

## Запуск локального прототипа

```bash
cd apps/web
npm install
npm run dev
```

Откройте `http://localhost:3000`.

Проверки:

```bash
npm run lint
npm run test
npm run build
```

Локальный интерфейс работает в режиме песочницы и не выполняет внешнюю отправку.

## Безопасность данных

Реальные документы хранятся локально в `data/raw/` и исключены из Git. Рабочие производные данные находятся в закрытых каталогах `data/working/`. В репозиторий нельзя коммитить реальные реквизиты, документы, ключи, токены и персональные данные.

`GET /api/pilot` возвращает только обезличенные агрегаты. Решения проверки и бизнес-события сохраняются как append-only записи с защитой от повторной команды через ключ идемпотентности.
